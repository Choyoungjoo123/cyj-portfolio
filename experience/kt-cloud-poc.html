KT Cloud 마켓플레이스 PoC

자사 AI 플랫폼(MLOps) 솔루션의 클라우드 사업자 환경 동작 검증 PoC 단독 수행

2026.10.14 ~ 10.27 (2주) 단독 수행 (설계·설치·검증·보고서 작성) 에이프리카 (AIFRICA) · 수습기간

한 줄 요약

자사 AI 플랫폼(MLOps) 솔루션이 국내 클라우드 사업자 환경에서 동작하는지 검증하는 PoC를 단독으로 수행하고 결과를 보고했습니다. 이 결과가 해당 클라우드 마켓플레이스 상품 등록으로 이어졌습니다.

배경과 목표

클라우드 사업자가 제공하는 GPU 인스턴스에서 자사 솔루션(v2.8.16)이 정상 동작하는지 검증하는 것이 목표였습니다.

제약 조건
  • 매니지드 서비스(EKS 등)를 사용하지 않고 온프레미스 방식으로 직접 설치
  • 공유 IAM 계정에 기간 제한 (~10/31)
  • 공인 IP 1개만 사용 가능

의사결정과 문제 해결 (강점)

① 중첩 가상화(KVM) 포기 → 직접 구성으로 전환

제한된 자원과 설치 복잡도를 고려해 중첩 가상화 대신 직접 구성 방식을 선택했습니다.

② MetalLB VIP 직접 노출 불가 → Static NAT + socat 포워딩 경로 설계

클라우드가 미등록 IP를 차단해 MetalLB VIP(172.25.20.175)로는 외부에서 접속할 수 없었습니다. 공인 IP를 Static NAT로 서버1(172.25.20.96)에 연결하고, 호스트의 socat(systemd 서비스)이 80·8000 포트를 MetalLB VIP로 넘겨 Istio Ingress Gateway까지 도달하는 경로를 설계해 해결했습니다.

③ 방화벽 최소 개방 원칙 적용

전체 포트를 여는 대신 서비스에 필요한 80(웹), 8000(모델 API), 30000~32767(NodePort)만 인바운드로 열고, SSH(22)는 회사 IP에서만 접근하도록 제한했습니다.

④ 설치 누락 설정 직접 탐지 및 해결 AI 도구 활용

로그 분석과 함께 AI 코딩 어시스턴트를 적극 활용해 원인 범위를 빠르게 좁히고, 누락된 설정들을 직접 찾아 해결했습니다.

  • cheetah-web-init의 multipart.storage-path ConfigMap 누락 → AI 도구로 관련 매니페스트·로그를 함께 분석해 원인을 특정하고 수동 패치
  • GPU Operator ConfigMap 누락 및 작업 큐 404 → AI 도구로 설정값을 교차 검증하며 원인을 좁혀 task-queue 설정을 추가해 해결
  • Airflow 이미지 버전 문제 → AI 도구와 공식 문서를 함께 대조해 버전 호환성 문제를 해결

⑤ 보고서의 과장 표현을 사실 기반으로 수정

"기능 오류 없이", "NAS 기반", "On-Premise 전환 검증" 같은 과장되거나 부정확한 표현을 실제 검증 범위에 맞게 사실 기반으로 고쳐서 제출했습니다.
